# DP7 Arboretum runtime implementation evidence

The new `arboretum_doors.js` owns this canonical room family with injected
Bedrock effects. It does not rewrite Guild v1 state, tickets, cells or payouts.
Root owns the main adapters/shared guards and reviewed integration; the geometry
owner authors the separate Arboretum and new Gorge throat.

Placement progresses `pending -> placed -> confirmed`. The immutable serial
index and exact dimension/origin/source precede source placement. The caller
records `placed` only after successful structure placement, and confirmed
source geometry is checked independently. Missing/ambiguous records quarantine
their indexed source; they never authorize source replay or a legacy persona.
Initialization also refuses surviving record or cell-reservation history.

There are at most 64 instances and 64 remembered Heroes per instance. Neither
limit evicts history. Fully evil means a supplied validated -1000 alignment;
the alternative counts ten actual qualified completed Crunchy Chick uses in
one unique locked source's six-block front-side vicinity. Heroes do not pool
progress, and the controller never consumes another item. Immediate same-tick
replay is suppressed. Native completed-use events expose no universal event ID,
so arbitrary delayed replay and crash durability are not claimed solved.

Arboretum has a separate bounded 4096-cell grid at `(620000,272,600000)`.
Its monotonic allocator commits reservations before effects, and every room
must match its immutable cell-owner record. One worker scans the full 67,228-cell
destination, then the main adapter performs a fresh pinned bulk air query with
unloaded chunks forbidden. Entity presence also refuses placement. Structure
placement is journaled before invocation; ambiguous placement is verified in
place and never replayed.

The full 9,794-cell barrier shell is checked in slices. Six final thin-volume
bulk checks establish fresh containment before readiness and before every
admission. Actual generated loop, reward branch, footprint/headroom, chest lid
and return markers are verified. One empty native chest receives one Wellow's
Pickhammer after a durable seed journal; exact item/count and other slots are
reread before ready. Ambiguous seeds never refill. Native collection owns the
transfer to the Hero, and later depletion does not authorize replenishment.

Own-family tickets preserve the exact approach, original door, instance and
cell. An occupied valid ticket remains a return/guard authority when the primary
index or instance record is missing, unavailable or replaced. Unavailable ticket
reads defer that visitor's mutation and travel. Other healthy visitors continue.
Checked returns are independent of another family's failed entry gate. Known
current rooms provide only their own absent/corrupt-ticket fallback, at the
supported Gorge bank row `source.z - 1`; old tickets never borrow another
instance's source. Guard unions cover allocated and actually occupied exact
cells, not the complete potential storage grid.

Only two bounded named leases exist: one room worker and one fair queued source
return loader. Opening faces and nearby portal shimmer are bounded, derived
presentation. They never own unlock/payment history. Public mutation at an
exhausted revision defers before changing state or reserving a cell.

The **27 passing runtime groups** execute the actual runtime and the current
owned Arboretum builder (filesystem save suppressed). They cover the complete
cold-build/entry/injected-container-depletion/return/reload path; two instances
and two Heroes; legacy/copy exclusions; limits and receipts; late occupancy and
shell changes; ignored/wrong seed writes; failed loading and teleport; source
and ticket loss; independent protections; and revision exhaustion. Exact
commands, hashes and earlier fixture failures are in
`arboretum-runtime-provenance.json`. The final output is
`arboretum-runtime-tests.log`.

Native acceptance, loading/query performance and engine crash atomicity remain
unrun. Destroying every related record, reservation and initialization witness
cannot be distinguished from a pristine world. The bounded pilot implements
the evil-alignment and witnessed-food paths; the original witnessed-murder
alternative and full visual-reference acceptance remain open. No broader base
gate or native pass is claimed by this subtask.
