## Current multiplier authority

`main.js:52` defines `P.get` as the raw dynamic property, defaulting only `undefined`; `P.add` applies JavaScript `+`. `main.js:1225` increments `fc_mult` by one on every player `entityHitEntity` with any target; it does not classify hostile targets, verify positive damage, or update this count for ordinary projectile/Will damage events. Player positive damage resets it at `1263`; player death resets it at `1297`. The 20-tick maintenance interval at `2964` subtracts two once inactivity exceeds 240 ticks. The HUD and menu only display this authority; they do not validate it. XP uses a capped transformation of the same raw value at `112`.

The actual extracted helper, hit callback and legacy requirement expression are exercised in `multiplier-audit.mjs` / `multiplier-audit-original.log`. Both numeric `14.5` and string `"14"` satisfy the current legacy threshold. Hitting a nonhostile cow increments numeric `13` to `14`, but string `"14"` becomes `"141"`. Unavailable reads throw. These observations concern the **preserved legacy contract**, not an implemented Greatwood Caves challenge.

A new canonical multiplier reader must independently read available raw `fc_mult`, require a finite integer at least 14, and revalidate the same live Hero, dimension, confirmed source, front-side range and authoritative locked record synchronously before unlock. It must neither normalize corrupted values nor use HUD/form text as proof. Threshold/current-property authority can be implemented offline; original damage scaling, target/action qualification, Physical Shield and area-transition reduction remain separate parity questions. No legacy Warrior/Harbinger entry or persona index should change.
