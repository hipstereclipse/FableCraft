# Faithful and original naming previews

L2 provides a single semantic name table in `scripts/fc_strings.py`. `name(key)`
raises on unknown keys or modes; `branding(mode)` restores its previous mode even
on failure. `text()` translates known display spellings, longest phrases first,
while preserving formatting, interpolation placeholders and unrelated accents.
`localize()` copies nested data without changing dictionary keys or numeric values.
Canonical `fc_data.py` and `fc_mobs.py` remain faithful source catalogs.

The original alternatives, including **Wayfarer Tales**, are provisional build
proposals. They are neither a final user-selected public title nor trademark clearance.
Generic gameplay terms such as Will, Hero, Guild, Assassin Rush and Silver Key remain
unchanged; distinctive place, creature, character and legendary-item names have pairs.
Context-sensitive names such as Thunder, Whisper and Scythe require release review.

## Build commands and ownership

```sh
python scripts/build_addon.py
python scripts/build_addon.py --branding faithful --preview
python scripts/build_addon.py --branding original --preview
python scripts/tests/test_branding.py
```

Every command that builds creates a fresh `tmp/builds/<mode>-<run>/` tree. It copies
the packs, regenerates the 194 data items and `fc_gamedata.js` through gen_behavior,
and regenerates the actual `en_US.lang` values through gen_resources. The language
keys, save/resource IDs, gameplay values and `languages.json` locale list stay stable.
The generator lore helper also resolves names; handwritten runtime lore follows in L3.
L3.3 also emits the expression registry and template-owned HUD runtime in staging.

`fc_branding.py` owns staged manifest display fields. Header names/descriptions and
author display names follow the mode; UUIDs, versions, dependencies and script entry
points remain the source values. Original preview metadata references Apache-2.0 and
the repository legal documents. Legal attribution is never run through name replacement.

The builder and both child auditors validate **the staging tree**. `verify_emotes.py`
and `audit_hud.py` accept `--root` for reproducible independent audits. Negative tests
break copied expression clips and HUD textures to prove failures refer to that tree.

Default faithful builds emit three local archives in the printed staging tree's `dist/`.
Preview mode emits no archives. `--branding original` without `--preview` fails before
writing files. Original packaging is also blocked inside the packaging function.
`--full` regenerates live faithful assets first; original previews reject `--full`.
Use targeted generators and the established behavior regression gate before broad regen.

## Remaining work

L3.1 now emits `fc_strings.js` from the same owner, with strict `name`, `t`, `template` and
canonical `itemName` accessors. The Hero Menu text and key inventory/map/status
messages are migrated. L3.2 migrates 95 legacy messages and reads saved place/title labels through explicit
compatibility lookups; L3.3 migrates logbook, expression and HUD display text; final vocabulary and in-world
review remain. See
[RUNTIME_NAMING.md](RUNTIME_NAMING.md) for the manual checklist.
L4 must scan all archived paths and contents, including escaped/case-varied names,
internal references and nested archives, with no release exemptions. Stable references
need a reviewed compatibility mapping before any packaging rename. See
[BRANDING_DEBT.md](BRANDING_DEBT.md) for the current display inventory.

Faithful builds never write to repository `dist/` now. The older tracked archives in
that directory remain legacy artifacts, unsuitable for public distribution. Nothing
generated by L2 is a public release. Do not stage local archives or preview pack trees.

Automated contracts cover both modes, generated data, lore, manifests, item stats,
language keys, error cleanup, live-pack hashes, auditor root selection and blocked
packaging. In-world menu rendering and compatibility remain unrun.
